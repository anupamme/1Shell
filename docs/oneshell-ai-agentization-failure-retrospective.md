# 1Shell AI Agent 化失败复盘

## 背景

1Shell AI 之前试图从“AI 辅助工作流”升级成 agent，但中途把太多外部结构叠到了模型外面：任务、Program、Skill、创作台、隐藏 planner、自动修复、前端合成旁白、决策策略改写等。结果不是让 AI 更会工作，而是让 AI 被一个越来越重的框架推着走。

这次清理后的目标不是重新堆一套更复杂的 agent 框架，而是回到更小的底层定义：

- 用户给目标。
- 模型看到完整上下文和可用工具。
- 模型自己决定下一步是回答、调用工具、继续观察，还是承认不确定。
- harness 只负责边界、权限、审计、事实记录和工具执行，不替模型规划、叙事或假装思考。

## 之前失败在哪里

### 1. 提示词堆叠被规避了，但架构堆叠没有

之前确实避免了把所有规则都塞进 system prompt，但同样的问题转移到了架构层：

- 外部框架预设“任务应该怎么走”。
- runtime 生成候选动作、计划、修复标签。
- 前端或服务端合成“我会根据错误改”一类叙事。
- 工具结果和模型输出被 UI 按固定槽位摆放，而不是按真实事件顺序呈现。

这会造成一种假象：界面上像有一个 agent 在工作，但真实决策可能已经被框架拆散、改写、排序或补全。

### 2. Task / Program / Skill 变成了模型语境污染

Task、Program 和 Skill 原本是给 1Shell AI 提供能力组织方式的，但后期变成了默认语境的一部分。问题不在于这些概念永远不能存在，而在于它们不应该默认压在普通对话 agent 上。

当模型每次都被塞进任务模板、Skill 清单、Program 结构时，它面对的就不是用户当前目标，而是一个先验工作流。它很容易开始套模板，而不是根据观察继续推理。

### 3. harness 从边界层滑向了行为层

harness 应该回答这些问题：

- 这个工具能不能执行？
- 是否需要用户批准？
- 输出里有没有需要脱敏的内容？
- 工具是否成功？
- 观察事实是什么？

harness 不应该回答这些问题：

- agent 下一步应该想什么？
- agent 应该如何措辞？
- agent 失败后必须执行哪套修复剧本？
- 最终总结应该放在哪里、以什么口吻出现？

一旦 harness 开始替模型安排行为，它就不再只是安全边界，而成了隐藏的操作者。用户看到的是 AI，实际服务用户的是框架。

### 4. 工具观察没有足够硬

agent 的底层循环依赖一件事：模型必须拿到清楚、可信、不可误读的观察。

之前的问题是，某些命令即使 `exitCode != 0`，也可能被包装成“工具调用成功”，失败只藏在普通文本里。这样模型看到的信号会很弱：它可能读取到 stdout 里一堆正常信息，然后忽略末尾的 `exitCode=127`，最后给出“整体正常”的总结。

正确做法不是塞一句“如果 exitCode 非 0 必须重试”，而是让工具结果本身表达事实：

- `ok=false`
- `is_error=true`
- `exitCode=127`
- stdout/stderr 摘要
- 失败原因或结构化 summary

模型可以自己决定是重试、解释部分未验证，还是继续检查。但它不能把失败观察误当成成功观察。

### 5. 前端丢失了事件顺序

前端 assistant turn 之前把文本和工具调用分成两个数组：

- `lines`
- `toolCalls`

这种结构天然丢失顺序。最终文本是在工具后生成的，但 UI 可能先渲染文本再渲染工具卡，于是用户看到“总结在最上方，工具在下方”。这不是 agent 的自然行为，而是 UI 状态模型把同一回合里的事件顺序压扁了。

正确做法是让 assistant turn 保留 ordered events。文本和工具仍可分别存储，便于兼容旧组件，但渲染应该按事件顺序走。

## 现在应该守住的边界

### 可以保留的底层能力

- 工具注册和调用。
- MCP / 主机 / 文件 / 命令能力。
- 权限、审批、审计、脱敏。
- 工具结果标准化。
- 对话历史和 tool_result 回灌。
- runtime ledger / trace，用于事后解释和安全追踪。

这些是 agent 的地基。

### 不应该默认回来的东西

- 默认任务 DSL。
- 默认 Program 语境。
- 默认 Skill roster 注入。
- 隐藏 planner 替模型规划。
- 隐藏 recovery script 替模型修复。
- 前端或服务端合成模型口吻。
- 决策策略改写模型工具参数。

这些东西可以作为未来可选产品能力重新设计，但不应该再悄悄进入默认 1Shell AI。

## 后续原则

1Shell AI 要 agent 化，不是要变成一个更复杂的工作流引擎。它应该先成为一个干净、诚实、可观察的工具型 agent：

- 上下文少而准。
- 工具结果硬而清楚。
- harness 管边界，不管思想。
- UI 呈现真实时间线，不重排行为。
- 失败要被看见，未验证要被承认。

真正的 agent 化不是让系统替 AI 表演“我在思考”，而是让 AI 在足够自由、足够清晰、足够安全的环境里自己完成观察、判断和行动。
