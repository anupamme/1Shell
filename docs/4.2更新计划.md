# 1Shell 4.2 更新计划

> 状态说明：本文件只记录 4.2 版本计划，不代表已经发布。

## 版本目标

4.2 不作为新的大方向版本，而是围绕 4.1 已经形成的主体闭环做补强。

本版本重点：

- 提升远程管理安全性，补齐登录 2FA。
- 降低 Claude Code、Codex 等外部 Agent 接入 1Shell MCP 的门槛。
- 强化程序板块，将高频 AI 工作流程序做成默认可用能力。
- 修复桌面版和主页体验中的关键问题。
- 修复沙箱、Agent 输出和状态显示中的重复渲染问题。
- 增加 GitHub、文档和反馈入口，方便用户了解项目并参与反馈。

## 已完成

### 公网直连探针安装修复

状态：完成

问题背景：

Relay 中继安装已经可用，但在“1Shell 本身部署在拥有公网 IP 的 VPS 上”时，直接安装 probe-agent 仍可能失败。核心原因是直连安装需要给目标 Agent 写入 `SERVER_URL`，而旧逻辑主要依赖后端从当前 HTTP 请求推导地址。在 1Panel/Nginx 反代、HTTPS 域名、Docker 映射端口等场景下，后端可能把真实公网 HTTPS 入口推导成内网地址、`http://` 地址或错误端口，导致 Agent 安装后无法下载二进制、注册或持续回传。

已完成内容：

- 新增 `PUBLIC_SERVER_URL` / `ONESHELL_PUBLIC_URL` 环境变量，允许部署者显式指定 1Shell 公网入口。
- 探针安装路由生成 `SERVER_URL` 时增加更稳的解析顺序：
  - 请求体显式传入的 `serverUrl`
  - `PUBLIC_SERVER_URL`
  - `X-Forwarded-Proto` + `X-Forwarded-Host`
  - 浏览器 `Origin`
  - 最后才退回当前请求协议和 `Host`
- 对多值反代头做首值解析，避免生成 `https,http://...` 这类错误 URL。
- Agent 端点信息接口同步支持 `PUBLIC_SERVER_URL`，减少 CLI/MCP 端点出现同类公网地址推导错误。
- `.env.example` 增加公网入口配置说明。

验收标准：

- 1Shell 直接部署在公网 VPS 上时，直连安装 probe-agent 能拿到正确的公网回连地址。
- 1Panel/Nginx HTTPS 反代后，未正确传递 `X-Forwarded-Proto` 时仍可优先使用 `PUBLIC_SERVER_URL` 或浏览器 `Origin`。
- Relay 安装路径不受影响。

- 后端同步新增空文件创建：
  - 文件服务 `createFile`（本机 `wx` 标志 / SFTP `wx` 打开，已存在时拒绝，避免静默清空）。
  - 路由 `POST /api/files/touch`。

### Docker 部署下的主机目录写入优化

状态：完成

问题背景：

Docker 部署场景下，1Shell 容器看到的是容器视角里的挂载目录。`/opt/1panel:ro`、`/www:ro` 等只读挂载导致 Claude Code、1Shell AI、文件管理器和 MCP 写文件工具都无法修改这些目录，且失败原因被泛化成"无法修改文件"。

已完成内容：

- 容器环境识别：Dockerfile 与 docker-compose 注入 `ONESHELL_IN_DOCKER=1`，代码同时探测 `/.dockerenv` 兜底。
- 只读错误识别与提示增强（`src/services/file.service.js`）：
  - 本机写入/上传/创建目录/创建文件/删除/重命名失败时，识别 `EROFS` / `EACCES` / `EPERM` / `read-only file system` / `permission denied` 类错误。
  - 自动执行写入自检（`data/tmp/1shell-write-test.txt`），区分"工具链不可用"和"目标路径不可写"。
  - Docker 环境下错误信息明确指出容器视角和只读挂载，并给出三条可执行处理方式（SSH 主机纳管 / `:ro` 改 `:rw` / `docker exec`）。
- 写入自检 API：`GET /api/files/write-check`，返回 `{ ok, path, error, inDocker }`。
- 命令执行层同步增强（`src/tools/oneshell-core.tools.js`）：容器内 local 主机的 `execute_command` / `host_exec` 因只读/权限失败时，在 stderr 追加同样的可行动提示，1Shell AI 和外部 Agent 都能直接看到（确定性实现，不依赖提示词，符合"安全与提示下沉执行层"的架构原则）。
- docker-compose.yml 重写挂载注释：解释容器视角与宿主机视角差异，给出"方案 A 只读浏览（默认）"与"方案 B 可写管理"两组配置。
- README Docker 部署节新增容器视角说明，与运行时错误提示口径一致。

验收结果：

- 后端语法检查通过；docker-compose YAML 校验通过。
- 行为测试：非 Docker 与 Docker 两种环境分支的错误增强文案验证通过；写入自检通过；提示包含三条可执行处理方式。
- install.sh 的 `--docker` 模式直接使用仓库 compose 文件，无需额外同步。

### 登录界面 2FA

状态：完成

已完成内容：

- 后端 TOTP 服务（`src/services/twofactor.service.js`，纯 Node crypto 实现，无新依赖）：
  - RFC 6238 TOTP，兼容 Google Authenticator 等认证器；±1 周期时钟容错；同周期验证码防重放。
  - 10 个一次性恢复码，只存 sha256 哈希，明文仅生成时返回一次。
  - 状态存 `data/2fa.json`（mode 0600）。
  - 行为测试 11/11 通过（启用/关闭/重放拒绝/恢复码一次性/错误码拒绝）。
- 登录两步流程（`auth.service.js` + `auth.routes.js`）：
  - 密码通过后签发 2 分钟有效的待验证票据（最多 5 次尝试），验证码通过才发正式会话。
  - `POST /api/auth/login/2fa`；失败计入 IP 锁定；错误信息保持通用不泄露配置细节。
  - 管理 API（需登录）：`GET /2fa/status`、`POST /2fa/setup`、`POST /2fa/enable`、`POST /2fa/disable`。
- 设置"安全"分区 2FA 管理：扫码（前端 `qrcode` 生成二维码）+ 手动密钥 + 验证码确认开启；恢复码一次性展示和复制；输入验证码/恢复码关闭（关闭后重开即重置）。
- 登录页改版（结合 ui-ux-pro-max 设计系统重做）：移除地球（LoginGlobe 已删除），左侧深色终端品牌区（模拟终端窗口 + 打字动画 + SVG 图标能力列表，终端内容为写死的演示文案，登录前不请求任何真实数据），右侧浅色登录卡片；2FA 验证码输入步骤；图标全部换为内联 SVG，错误提示带 `role="alert"`，动画遵守 `prefers-reduced-motion`。
- 初次部署默认浅色模式：`frontend/index.html` 内联脚本与 `main.ts` 改为默认浅色，仅 `localStorage['1shell-theme']==='dark'` 时用深色，已设置过的用户偏好不受影响（该项原计划单列，已随本项一并完成）。
- 设置由弹窗改为独立页面（`/settings`，`SettingsView.vue`）：左侧分区导航（账号/安全/IP 访问控制/AI 配置/桌面版），支持 `?tab=` 深链；SettingsModal 与 useSettingsModal 已删除；顺带修复浅色模式下设置页/主机弹窗等输入框文字继承白色看不清的问题。

验收结果：

- 浏览器端到端验收通过：登录页视觉、2FA 完整开启→两步登录→关闭流程、独立设置页各分区均经用户实测确认正常。
- 前端 TypeScript 类型检查与构建通过。

### 沙箱输出残影与重复渲染修复

状态：待做

目标：

修复沙箱、Agent 执行过程或状态检查结果偶尔出现“残影”的问题。当前表现为同一段输出在界面上重复显示，容易让用户误以为命令被执行了两次，或 Agent 的状态判断发生了异常。

可能原因：

- 流式输出追加时，同一段增量内容被重复写入。
- Agent 状态刷新后，历史消息与最新消息被同时渲染。
- 前端消息列表缺少稳定的消息 ID 或 chunk ID 去重。
- 沙箱执行结束后的最终总结与中间状态复用了同一段文本。
- 组件重新渲染时没有正确清理旧的输出缓存。

计划内容：

- 检查沙箱输出、Agent 日志、状态检查结果的消息生成和前端渲染流程。
- 为流式输出 chunk、执行步骤、状态消息增加稳定标识，避免重复追加。
- 在前端渲染层增加必要的去重保护。
- 区分“命令实际执行次数”和“界面显示次数”，避免重复渲染被误判为重复执行。
- 对长输出、状态刷新、页面切换后返回等场景进行验证。

验收标准：

- 同一次沙箱执行中，相同状态文本不会无故重复显示。
- 页面切换、状态刷新、流式输出结束后不会留下重复残影。
- 修复不影响正常的多轮输出、连续日志和重复内容本身的展示。
